## Bevor du anfängst

Aktiviere zuerst die [Figma-Bibliotheken](/de/dokumentation/lernen/figma-einrichten 'Zugang holen und Bibliotheken aktivieren.'). Dasselbe Formular im Code zeigt das [React-Tutorial](/de/dokumentation/lernen/react-tutorial 'Dasselbe Kontaktformular im Code.').

<LearnAside>

Du gestaltest ein Kontaktformular mit Name, E-Mail, Thema, Nachricht und einer Bestätigung nach dem Absenden. Jeder Schritt endet mit einer Prüfung. So weißt du, dass der Schritt funktioniert hat, bevor du weitermachst.

Du brauchst:

- Zugang zu den Figma-Bibliotheken des DB UX Design Systems
- Einen Figma-Seat, mit dem du Dateien bearbeiten kannst. Mit einem Dev-Seat kannst du Designs untersuchen, aber nicht anlegen.
- Grundkenntnisse in Figma: Frames, Auto Layout und Komponenten-Instanzen

Lege zum Start eine neue Design-Datei in der Figma-Organisation der Deutschen Bahn an, öffne das Assets-Panel, wähle **Libraries** und aktiviere **DB UX - Core Foundation** und **DB UX - Core Components**. Core Foundation enthält die Variablen für Farben, Abstände und Typografie, die die Komponenten nutzen.

**Prüfen:** Eine Suche nach „Button“ im Assets-Panel findet `Button → Brand` aus DB UX - Core Components.

Die Namen der Properties beginnen in Figma mit einem Icon, das ihren Zweck zeigt, zum Beispiel ✏️ für Texte und 📦 für Slots. Dieses Tutorial nennt die Properties so, wie sie im Properties-Panel stehen. Die Icons sind unter [Figma-Bibliotheken einrichten](/de/dokumentation/lernen/figma-einrichten#arbeite-mit-den-komponenten-über-ihre-properties) erklärt.

</LearnAside>

</LearnBlock>

## Baue die Seitenstruktur auf

Lege einen Seiten-Frame mit vertikalem Auto Layout an, verknüpfe seinen Abstand mit der Variable `db-spacing/fixed/lg` und füge eine Überschrift ein.

<LearnAside>

1. Lege einen Frame für die Seite an und gib ihm ein vertikales Auto Layout.
2. Verknüpfe den Abstand des Auto Layouts mit der Variable `db-spacing/fixed/lg`. Klicke dafür auf den Abstandswert und wähle die Variable, statt eine Zahl einzutippen.
3. Füge `Heading H1 (Beta)` ein und setze **✏️ Text** auf „Kontakt“.

Variablen statt fester Werte halten deine Abstände passend zur Density, und Entwickler:innen sehen im Dev Mode das passende Token.

**Prüfen:** Die Überschrift erscheint in der Headline-Schrift des DB Themes. Wählst du den Abstand des Frames aus, zeigt er die Variable `db-spacing/fixed/lg` statt eines Pixelwerts.

</LearnAside>

</LearnBlock>

<LearnBlock>

## Setze das Formular in eine Card

Füge unter der Überschrift eine Card ein und setze fünf Formularfelder und einen Button in ihren Slot **📦 Children**. Ändere die Komponenten nur über ihre Properties und Slots und löse sie nie von der Komponente (Detach).

<LearnAside>

1. Füge unter der Überschrift `Card → (Def) Level 1 (Beta)` ein und setze **🔀 Spacing** auf **Medium**.
2. Gib dem Slot **📦 Children** der Card ein vertikales Auto Layout mit dem Abstand `db-spacing/fixed/md`.
3. Setze diese Komponenten in den Slot und trage ihre Texte ein:

| Komponente                                   | Property | Wert                 |
| -------------------------------------------- | -------- | -------------------- |
| `Input → (Def) Label Above - (Def) Empty`    | ✏️ Label | Name                 |
| `Input → (Def) Label Above - (Def) Empty`    | ✏️ Label | E-Mail               |
| `Select → (Def) Label Above - (Def) Empty`   | ✏️ Label | Thema                |
| `Textarea → Label Above - (Def) Empty`       | ✏️ Label | Nachricht            |
| `Checkbox → (Def) Medium - (Def) Auto Width` | ✏️ Label | Kopie an mich senden |
| `Button → Brand`                             | ✏️ Text  | Nachricht senden     |

4. Schalte beim Button **👁️ Show Icon Leading** ein und tausche **🔄 Icon Leading Medium** gegen das Icon `arrow_right`.

Bearbeite die Ebenen einer Komponente nicht direkt. Die Properties entsprechen den Properties im Code – eine gelöste Instanz verliert diese Verbindung, und Entwickler:innen können daraus keinen korrekten Code mehr ablesen.

**Prüfen:** Die Card zeigt fünf Felder und einen Button in der Markenfarbe mit Pfeil. Im Ebenen-Panel ist jedes Feld weiterhin eine Instanz (Komponenten-Icon) und kein Frame.

</LearnAside>

</LearnBlock>

<LearnBlock>

## Markiere die Pflichtfelder

Setze bei Name, E-Mail und Nachricht **⚙️ Required** auf true und schalte **👁️ Show Required Asterisk** ein. Prüfen: Diese drei Felder zeigen ein Sternchen, Thema und die Checkbox nicht.

<LearnAside>

**⚙️ Required** ändert das Aussehen nicht – die Property teilt dem Code nur mit, dass das Feld Pflicht ist. **👁️ Show Required Asterisk** zeigt Nutzer:innen, welche Felder Pflicht sind.

Properties mit ⚙️ wirken nur im Code. Setze sie trotzdem, damit das Snippet im Dev Mode vollständig ist. Mehr dazu unter [Code Connect](/de/dokumentation/lernen/code-connect).

</LearnAside>

</LearnBlock>

## Gestalte den Zustand nach dem Absenden

Entwickler:innen müssen wissen, was nach dem Absenden passiert. Dupliziere die Seite und zeige auf der Kopie eine Erfolgsmeldung mit der Notification.

<LearnAside>

1. Dupliziere den Seiten-Frame und benenne die Kopien „Kontakt – Formular“ und „Kontakt – Gesendet“.
2. Füge in „Kontakt – Gesendet“ zwischen Überschrift und Card `Notification → Standalone - (Def) Icon` ein.
3. Setze **🔀 Semantic** auf **Successful**.
4. Setze **🔀 Show Headline** auf **True**.
5. Setze **✏️ Headline** auf „Nachricht gesendet“ und **✏️ Text** auf „Wir melden uns innerhalb von zwei Werktagen bei dir.“
6. Schalte **🔀 Closeable** ein.

**Prüfen:** „Kontakt – Gesendet“ zeigt über der Card eine grüne Meldung mit Icon und Schließen-Button. „Kontakt – Formular“ ist unverändert.

</LearnAside>

</LearnBlock>

## Prüfe die Übergabe im Dev Mode

Wechsle mit `Shift` + `D` in den Dev Mode und wähle die Komponenten nacheinander aus. Dank Code Connect zeigt jede ihren Code mit einer `DB`-Komponente statt allgemeinem CSS.

<LearnAside>

### Die Snippets

Wähle das Feld Name aus. Das Snippet sieht so aus:

```tsx
<DBInput
	variant="above"
	label="Name"
	showLabel={true}
	required={true}
	showRequiredAsterisk={true}
	readonly={false}
	disabled={false}
	validation="no-validation"
	showIconLeading={false}
	showIconTrailing={false}
	showMessage={false}
	name="input"
/>
```

- `label` und `required` kommen aus **✏️ Label** und **⚙️ Required**. Fehlt `required={true}`, fehlt bei diesem Feld der vorige Schritt.
- Properties mit Standardwerten wie `disabled={false}` gehören zum Snippet. Entwickler:innen können sie weglassen.
- `name="input"` ist ein Platzhalter. Den echten Feldnamen legt der Code fest.

Wähle die Card aus. Ihr Snippet beginnt mit:

```tsx
<DBCard elevationLevel="1" spacing="medium" behavior="static">
```

**Prüfen:** Jede Komponente des Formulars zeigt ein Snippet mit einer `DB`-Komponente – `DBHeadingH1`, `DBCard`, `DBInput`, `DBSelect`, `DBTextarea`, `DBCheckbox`, `DBButton` und `DBNotification`. Zeigt eine Komponente nur CSS, ist sie gelöst oder stammt nicht aus den DB UX-Bibliotheken.

### Was die Entwicklung ergänzt

Manches lässt sich nicht gestalten. Stimme es bei der Übergabe ab oder notiere es in der Datei:

| Thema                       | Woher es kommt                                                                                          |
| --------------------------- | ------------------------------------------------------------------------------------------------------- |
| Optionen des Selects        | Die Entwicklung ergänzt sie als `<option>`-Elemente. Liste die Optionen in einer Notiz am Screen auf.   |
| Feldnamen                   | Werden im Code gesetzt, zum Beispiel `name="email"`.                                                    |
| Verhalten nach dem Absenden | Die Entwicklung zeigt die Meldung, sobald das Formular gesendet wurde. Dein zweiter Screen zeigt, wann. |
| Layout-Frames               | Frames sind keine Komponenten. Die Entwicklung baut sie mit Layout-Komponenten und Tokens nach.         |

</LearnAside>
