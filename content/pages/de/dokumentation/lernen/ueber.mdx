## Was das Design System ist

Das DB UX Design System ist die gemeinsame Basis für die digitalen Produkte der Deutschen Bahn. Design und Entwicklung nutzen dieselbe Foundation, dieselben Komponenten und dieselben Namen – in Figma und im Code.

Diese Dokumentation beschreibt **Generation 3**, die aktuelle Generation. Ihr Vorgänger ist Generation 2, früher bekannt als DB UI. Wenn du noch damit arbeitest, beginne mit der [Migration von DB UI](/de/dokumentation/lernen/migration).

</DBSection>

<DBSection spacing="small" width="auto">

## Was es enthält

| Bestandteil   | Inhalt                                                                                              | Dokumentation                                                                                                  |
| ------------- | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Foundation    | Tokens für Farben, Typografie, Abstände, Density und mehr                                           | [Foundation](/de/dokumentation/foundation)                                                                     |
| Komponenten   | Bausteine für Interfaces in Design und Code                                                         | [Komponenten](/de/dokumentation/komponenten)                                                                   |
| Pattern       | Wiederkehrende Lösungen, die mehrere Komponenten kombinieren                                        | [Pattern](/de/dokumentation/pattern)                                                                           |
| Erweiterungen | Zusätzliche Bibliotheken für bestimmte Bereiche, etwa Reisendeninformation oder Datenvisualisierung | [Erweiterungen](/de/dokumentation/erweiterungen)                                                               |
| Themes        | Das DB Theme und das S-Bahn Theme, die die Marke auf alles oben Genannte bringen                    | [DB Theme](/de/dokumentation/ressourcen/pakete/db-theme)                                       |
| Werkzeuge     | Figma-Bibliotheken und Plugins, Code-Pakete, der MCP Server für KI-Agenten                          | [Design-Ressourcen](/de/dokumentation/ressourcen/design), [Pakete](/de/dokumentation/ressourcen/pakete) |

Der Kern des Systems ist für alle Produkte gleich. Erweiterungen bauen für bestimmte Bereiche darauf auf.

### Plattformen

Die Komponenten gibt es für das Web: als CSS, als Web Components und für Angular, React und Vue. Native Komponenten für iOS (SwiftUI) und Android (Jetpack Compose) entstehen in eigenen Repositories – siehe [Native Plattformen](/de/dokumentation/ressourcen/pakete/native).

## Wie es veröffentlicht wird

Das Design System folgt der semantischen Versionierung: `MAJOR.MINOR.PATCH`.

| Release | Inhalt                                          | Rhythmus                                                  |
| ------- | ----------------------------------------------- | --------------------------------------------------------- |
| Major   | Breaking Changes                                | geplant, mindestens 2–3 Monate Abstand, vorab angekündigt |
| Minor   | neue Funktionen, vollständig abwärtskompatibel  | im Zwei-Wochen-Rhythmus der Sprints                       |
| Patch   | Fehlerbehebungen und sehr kleine Verbesserungen | nach Bedarf                                               |

Major- und Minor-Versionsnummern sind zwischen Design und Entwicklung synchron. Die Details inklusive aller Kommunikationskanäle stehen unter [Versionierung](/de/dokumentation/releases/versionierung).

</DBSection>

## Was ein Status bedeutet

Jede Komponente, jedes Pattern und jedes Template hat einen Status. Er zeigt, wie ausgereift und verlässlich der Inhalt ist.

| Status     | Bedeutung                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------- |
| Concept    | Früher Ansatz, nichts ist final. Als Design-Referenz nutzbar – eine Implementierung im Code gibt es eventuell noch nicht. |
| Beta       | Funktionsfähig und weitgehend stabil. Kleinere Änderungen sind noch möglich. Teste gründlich und gib Feedback.            |
| Stable     | Ausgereift und verlässlich. **Verpflichtend** als UX-Standard.                                                            |
| Legacy     | Wird nicht mehr aktiv weiterentwickelt, nur noch kritische Fehlerbehebungen. Migriere auf aktuelle Inhalte.               |
| Deprecated | Wird in einem kommenden Major-Release entfernt. Plane den Ersatz ein.                                                     |

Was du von jedem Status im Detail erwarten kannst, steht unter [Content Status](/de/dokumentation/releases/content-status). Den aktuellen Status jeder Komponente zeigt das [Board zum Komponentenstatus](https://github.com/orgs/db-ux-design-system/projects/4/views/1).

</DBSection>

<DBSection spacing="small" width="auto">

## Wie verbindlich es ist

| Bestandteil                | Verbindlichkeit                                                                                      |
| -------------------------- | ---------------------------------------------------------------------------------------------------- |
| Inhalte mit Status Stable  | **verpflichtend** als UX-Standard                                                                    |
| Inhalte mit Status Beta    | empfohlen – teste gründlich und gib Feedback                                                         |
| Inhalte mit Status Concept | nur als Design-Referenz, mit Änderungen ist zu rechnen                                               |
| DB Theme                   | **erforderlich** für alle Websites und Anwendungen der Deutschen Bahn, außerhalb davon nicht erlaubt |

Bei Fragen zur Einführung des Design Systems in deinem Produkt wende dich an Luis Schroff, den Product Owner des Design Systems: [luis.schroff@deutschebahn.com](mailto:luis.schroff@deutschebahn.com).

</DBSection>
