## Eine Basis für Design und Code

Das DB UX Design System ist die gemeinsame Basis für die digitalen Produkte der Deutschen Bahn. Design und Entwicklung nutzen dieselbe Foundation, dieselben Komponenten und dieselben Namen – in Figma und im Code.

Diese Dokumentation beschreibt Generation 3, die aktuelle Generation.

</LearnBlock>

<LearnBlock>

## Was es enthält

Die Foundation für die Tokens, Komponenten als Bausteine, Pattern, die sie kombinieren, Erweiterungen für besondere Bereiche und Themes, die die Marke anwenden. Die Komponenten gibt es für CSS, Web Components, Angular, React und Vue.

<LearnAside>

| Bestandteil   | Inhalt                                                                | Dokumentation                                            |
| ------------- | --------------------------------------------------------------------- | -------------------------------------------------------- |
| Foundation    | Tokens für Farben, Typografie, Abstände und Density                   | [Foundation](/de/dokumentation/foundation)               |
| Komponenten   | Bausteine für Interfaces in Design und Code                           | [Komponenten](/de/dokumentation/komponenten)             |
| Pattern       | Wiederkehrende Lösungen, die mehrere Komponenten kombinieren          | [Pattern](/de/dokumentation/pattern)                     |
| Erweiterungen | Bibliotheken für Bereiche wie Reisendeninformation oder DataViz       | [Erweiterungen](/de/dokumentation/erweiterungen)         |
| Themes        | Bringen eine Marke auf alles oben Genannte, zum Beispiel das DB Theme | [DB Theme](/de/dokumentation/lernen/db-theme-einrichten) |

Native Komponenten für iOS und Android gibt es in [eigenen Paketen](#native-plattformen).

Wähle das Paket für dein Framework. Jeder Setup-Artikel führt dich von der Installation bis zur ersten Komponente.

| ---------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------- |

| Vue                          | `@db-ux/v-core-components`     | [Komponenten in Vue einbinden](/de/dokumentation/lernen/vue-einrichten)                     |

Du startest ein neues Projekt mit React? Das [React-Tutorial](/de/dokumentation/lernen/react-tutorial) führt dich von einem leeren Projekt zu einem funktionierenden Formular, mit einer Prüfung nach jedem Schritt.

#### Wie die Pakete zusammenhängen

Drei Schichten bauen aufeinander auf. Du installierst nur die oberste, die du brauchst – die darunterliegenden kommen mit.

| Schicht               | Paket                                                                               | Inhalt                                                       |
| --------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Framework-Komponenten | `@db-ux/react-core-components` und die Pendants für Angular, Vue und Web Components | Komponenten für ein Framework                                |
| Komponenten-Styles    | `@db-ux/core-components`                                                            | CSS und SCSS aller Komponenten, enthält die Schicht darunter |
| Tokens und Assets     | `@db-ux/core-foundations`                                                           | Farben, Abstände, Typografie, Density, Icons, Schriften      |

`@db-ux/core-components` zieht `@db-ux/core-foundations` als Abhängigkeit mit. Bei npm passiert das automatisch. Bei pnpm installierst du beide explizit.

#### Themes und Assets

Alle Setup-Artikel für Frameworks nutzen das Whitelabel-Theme, weil es ohne weiteren Zugang funktioniert. Produkte der Deutschen Bahn brauchen zusätzlich das DB Theme – ohne es bleiben Farben, Typografie und Assets auf den Whitelabel-Standardwerten. Theme und Icons sind verschlüsselt und brauchen Zugangsdaten aus dem Marketingportal.

| Ziel                | Installation            | Anleitung                                                                         |
| ------------------- | ----------------------- | --------------------------------------------------------------------------------- |
| Marke Deutsche Bahn | `@db-ux/db-theme`       | [DB Theme für DB-Produkte ergänzen](/de/dokumentation/lernen/db-theme-einrichten) |
| Marke S-Bahn        | `@db-ux/s-bahn-theme`   | [S-Bahn Theme](/de/dokumentation/lernen/db-theme-einrichten#s-bahn-theme)         |
| Icons ohne Theme    | `@db-ux/db-theme-icons` | [Icons im Interface anzeigen](/de/dokumentation/lernen/icons-einrichten)          |

#### Optionales Tooling

Keines dieser Pakete brauchst du für den Start. Ergänze sie, sobald deine erste Komponente erscheint. Die Konfiguration steht im Setup-Artikel deines Frameworks.

| Paket                        | Zweck                                                                                                             | Empfehlung                       |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| `@db-ux/core-postcss-plugin` | Löst `var()`, `calc()`, `color-mix()` und `light-dark()` zur Build-Zeit auf und entfernt ungenutzte Deklarationen | Empfohlen für Produktions-Builds |
| `@db-ux/core-vite-plugin`    | Reduziert das CSS-Setup auf einen einzigen Import                                                                 | Empfohlen, wenn du Vite nutzt    |
| `@db-ux/core-eslint-plugin`  | Meldet falsche Komponentennutzung im Editor                                                                       | Optional, im Team aber hilfreich |
| `@db-ux/core-stylelint`      | Prüft dein CSS und SCSS gegen die Regeln des Design Systems                                                       | Optional                         |

Für KI-Coding-Agenten gibt es `@db-ux/mcp-server` und `@db-ux/agent-cli`. Beide beschreibt der [Artikel zum MCP Server](/de/dokumentation/lernen/mcp-server).

### Native Plattformen

Die nativen Bibliotheken für iOS (SwiftUI) und Android (Jetpack Compose) sind in Entwicklung. Keine der beiden hat ein veröffentlichtes Release, und eine Installationsanleitung für Produkte gibt es noch nicht. Die Repositories beschreiben, wie du das Projekt zum Mitwirken einrichtest, nicht, wie du es in einer App nutzt.

| Plattform | Technologie                     | Mindestversion | Repository                                                          |
| --------- | ------------------------------- | -------------- | ------------------------------------------------------------------- |
| iOS       | SwiftUI, Swift Package `DBUXDS` | iOS 18         | [core-ios](https://github.com/db-ux-design-system/core-ios)         |
| Android   | Jetpack Compose                 | Android API 30 | [core-android](https://github.com/db-ux-design-system/core-android) |

Beide Bibliotheken gliedern sich in **Foundation** – Farben, Typografie und Abstände als Tokens – und **Komponenten**.

| Komponente | iOS | Android |
| ---------- | --- | ------- |
| Accordion  | ✅  | ✅      |
| Badge      | ✅  | ✅      |
| Button     | ✅  | ✅      |
| Card       | ✅  | ✅      |
| Checkbox   | ✅  | ✅      |
| Icon       | –   | ✅      |
| Infotext   | ✅  | ✅      |
| Link       | ✅  | ✅      |

Die Liste gibt den Quellcode in den Repositories wieder. Über den Status einer Komponente sagt sie nichts aus – die Web-Komponenten und ihr Status sind unter [Komponenten](/de/dokumentation/komponenten) dokumentiert.

## Jeder Inhalt hat einen Status

Ein Status zeigt dir, wie ausgereift eine Komponente, ein Pattern oder ein Template ist. **Stable** ist als UX-Standard verpflichtend, **Beta** ist empfohlen, **Concept** ist nur eine Design-Referenz.

<LearnAside>

Was jeder Status im Detail bedeutet, steht unter [Was ein Status bedeutet](/de/dokumentation/lernen/status). Releases folgen der semantischen Versionierung: Major-Releases werden vorab angekündigt, Minor- und Patch-Releases erscheinen laufend – siehe [Wie Releases funktionieren](/de/dokumentation/lernen/versionierung).

</LearnAside>

</LearnBlock>

## Wie verbindlich es ist

Inhalte mit Status Stable sind der verpflichtende UX-Standard. Das DB Theme ist für alle Websites und Anwendungen der Deutschen Bahn erforderlich und darf außerhalb davon nicht verwendet werden.

<LearnAside>

Der Code des Design Systems steht unter der Apache-2.0-Lizenz. Das DB Theme und seine Assets sind die Ausnahme: Sie dürfen nur für Websites und Anwendungen der Deutschen Bahn verwendet werden.

</LearnAside>

</LearnBlock>
