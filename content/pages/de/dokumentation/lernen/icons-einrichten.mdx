## Funktionale Icons

**Funktionale Icons** stehen in Komponenten und im Fließtext.

<LearnAside>

| Paket                   | Inhalt                                     | Nutze es für                          |
| ----------------------- | ------------------------------------------ | ------------------------------------- |
| `@db-ux/db-theme-icons` | Funktionale Icons als Icon-Schrift und SVG | Icons in Komponenten und im Fließtext |

Wenn du [das DB Theme ergänzt](/de/dokumentation/lernen/db-theme-einrichten) hast, ist das Paket schon in deinem Projekt und das Theme lädt die Icon-Schrift. Überspringe dann Installation und Styles und mach mit dem ersten Icon weiter.

</LearnAside>

</LearnBlock>

<LearnBlock>

## Installiere die funktionalen Icons

Das Paket braucht dieselben Zugangsdaten wie das DB Theme.

```shell
pnpm add @db-ux/db-theme-icons
```

<LearnAside>

- **Zugangsdaten:** Das Paket ist wie das DB Theme verschlüsselt. Es braucht `ASSET_PASSWORD` und `ASSET_INIT_VECTOR` aus dem Marketingportal in deiner `.env`-Datei, wie in [DB Theme für DB-Produkte ergänzen](/de/dokumentation/lernen/db-theme-einrichten) beschrieben. Ein `postinstall`-Skript entschlüsselt die Dateien.
- **pnpm:** Erlaube das Install-Skript mit `pnpm approve-builds`.
- **npm:** Nutze `npm i @db-ux/db-theme-icons`.

</LearnAside>

</LearnBlock>

<LearnBlock>

## Lade die Icon-Schrift

Die Icons werden als Schrift ausgeliefert. Importiere die Style-Datei, die zu deinem Bundler passt.

```css
/* src/index.css */
@import '@db-ux/db-theme-icons/build/styles/rollup.css';
```

<LearnAside>

### Die passende Datei für deinen Bundler

| Datei                              | Nutze sie, wenn …             |
| ---------------------------------- | ----------------------------- |
| `rollup.css`                       | du mit Vite oder Rollup baust |
| `webpack.css`                      | du mit Webpack baust          |
| `relative.css` oder `absolute.css` | du keinen Bundler nutzt       |

Alle Dateien liegen unter `@db-ux/db-theme-icons/build/styles/`.

### Standard-Icons überall ersetzen

Die Komponenten bringen ein Standard-Icon-Set mit. Um es in allen Komponenten durch die DB-Icons zu ersetzen, importiere zusätzlich `default-font.css`:

```css
@import '@db-ux/db-theme-icons/build/styles/default-font.css';
```

### Autovervollständigung für Icon-Namen

Trage die generierten Typen in deine `tsconfig.json` ein:

```json
{
	"compilerOptions": {
		"types": ["@db-ux/db-theme-icons"]
	},
	"include": ["node_modules/@db-ux/db-theme-icons/build/types/overwrite.d.ts"]
}
```

Für React oder Vue bindest du stattdessen `build/types/react.d.ts` oder `build/types/vue.d.ts` ein.

</LearnAside>

</LearnBlock>

## Zeige dein erstes Icon an

Setze den Icon-Namen an der Komponente. `data-icon-variant="db"` wählt für dieses Element die DB-Icon-Schrift.

```tsx
<DBButton icon="arrow_right" data-icon-variant="db">
	Weiter
</DBButton>
```

<LearnAside>

### Angular und HTML

```html
<!-- Angular -->
<db-button icon="arrow_right" data-icon-variant="db">Weiter</db-button>

<!-- HTML und CSS -->
<button class="db-button" data-icon="arrow_right" data-icon-variant="db">Weiter</button>
```

Alle verfügbaren Namen stehen in der [Icon-Liste](/de/dokumentation/icons). Das React-Beispiel funktioniert in Vue genauso.

### Icons außerhalb von Komponenten

Kopiere die SVG-Dateien aus `node_modules/@db-ux/db-theme-icons/build/assets`.

</LearnAside>

</LearnBlock>

## Passe Größe, Family und Farbe an

`data-icon-weight` wählt die Schrift für die Icon-Größe, `data-icon-variant="db-filled"` die gefüllte Family. Die Farbe kommt aus `--db-icon-color`.

```html
<span data-icon="user" data-icon-weight="32" data-icon-variant="db-filled">Profil</span>
```

<LearnAside>

### Größen

Jede Größe hat eine eigene Schrift mit mehr oder weniger Details. Die DB-Icons gibt es in `12`, `14`, `16`, `20`, `24` und `32`. Die Standard-Icons der Komponenten ohne DB Theme gibt es in `16`, `20`, `24`, `32`, `48` und `64`.

Um ein Icon genauer zu skalieren, setze zusätzlich `--db-icon-font-size`. Behalte ein `data-icon-weight` nahe am Ergebnis, damit der Detailgrad passt.

### Icons vor und nach dem Text

`data-icon` setzt ein Icon vor den Text, `data-icon-trailing` dahinter. Größe und Family setzt du pro Seite:

| Seite    | Größe                          | Family                                 |
| -------- | ------------------------------ | -------------------------------------- |
| beide    | `data-icon-weight="24"`        | `data-icon-variant="db-filled"`        |
| davor    | `data-icon-weight-before="24"` | `data-icon-variant-before="db-filled"` |
| dahinter | `data-icon-weight-after="24"`  | `data-icon-variant-after="db-filled"`  |

Ohne DB Theme heißen die Families `default` und `filled`.

### Gefüllte Form

Nicht jedes Icon hat eine eigene gefüllte Form. Die [Icon-Liste](/de/dokumentation/icons) zeigt, welche.

### Farbe

`--db-icon-color` überschreibt die Farbe der Icon-Schriften und der SVG-Dateien.

</LearnAside>

## Wenn ein Icon nicht erscheint

Die meisten Probleme kommen von einer nicht geladenen Icon-Schrift oder einem fehlenden `data-icon-variant`.

<LearnAside>

| Symptom                                                | Ursache und Lösung                                                                                                                          |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Icons erscheinen als leere Kästchen oder Ersatzzeichen | Die Icon-Schrift ist nicht geladen. Importiere die Styles oder prüfe, ob die Dateivariante zu deinem Bundler passt.                         |
| Statt der DB-Icons erscheinen die Standard-Icons       | `default-font.css` ist nicht importiert oder `data-icon-variant="db"` fehlt am Element.                                                     |
| Der Build scheitert mit `ENOENT` im Paket              | Die Assets wurden nie entschlüsselt. Erlaube das Install-Skript oder [entschlüssele manuell](/de/dokumentation/lernen/db-theme-einrichten). |
| Ein Icon-Name wird nicht erkannt                       | Den Namen gibt es nicht. Prüfe die Schreibweise in der [Icon-Liste](/de/dokumentation/icons).                                               |

Wenn nichts davon hilft, eröffne ein Issue im [core-web-Repository](https://github.com/db-ux-design-system/core-web/issues/new/choose). Prüfe vorher, ob es das Issue schon gibt.

</LearnAside>

### Eigene Icons nutzen

Eigene Icons müssen wie die DB-Icons als **woff2**-Icon-Schrift vorliegen. Erzeuge sie aus deinen SVG-Dateien mit den [icon-font-tools](https://github.com/db-ux-design-system/icon-font-tools/blob/main/docs/GenerateIconFonts.md). Das Beispielprojekt [custom-theme-example](https://github.com/db-ux-design-system/examples/tree/main/custom-theme-example) zeigt ein Theme mit eigener Icon-Schrift.

Für die Autovervollständigung deiner eigenen Icon-Namen erweiterst du die Icon-Typen:

```ts
import '@db-ux/core-foundations';
import { IconTypes } from '@db-ux/db-theme-icons';

declare module '@db-ux/core-foundations' {
	interface OverwriteIcons {
		types: IconTypes | 'my-custom-icon';
	}
}
```
