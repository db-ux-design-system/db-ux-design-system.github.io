## Funktionale Icons

### Installation

```shell
npm i @db-ux/db-theme-icons
```

### Styling-Setup

Die Icons werden als Schrift ausgeliefert. Importiere die Variante, die zu deinem Bundler passt.

```css
/* index.css */
@import '@db-ux/db-theme-icons/build/styles/rollup.css';
```

| Variante                           | Nutze sie, wenn               |
| ---------------------------------- | ----------------------------- |
| `rollup.css`                       | du mit Vite oder Rollup baust |
| `webpack.css`                      | du mit Webpack baust          |
| `relative.css` oder `absolute.css` | du keinen Bundler nutzt       |

### Standard-Icons ersetzen

Die Komponenten bringen ein Standard-Icon-Set mit. Um es überall durch die DB-Icons zu ersetzen, importiere `default-font.css`:

```css
/* index.css */
@import '@db-ux/db-theme-icons/build/styles/default-font.css';
```

### Erstes Icon

Setze den Icon-Namen an der Komponente. `data-icon-variant="db"` wählt für dieses Element die DB-Icon-Schrift.

```tsx
// React und Vue
<DBButton icon="my_icon" data-icon-variant="db">
	Test
</DBButton>
```

```html
<!-- Angular -->
<db-button icon="my_icon" data-icon-variant="db">Test</db-button>

<!-- HTML und CSS -->
<button class="db-button" data-icon="my_icon" data-icon-variant="db">Test</button>
```

Ersetze `my_icon` durch einen Namen aus der [Icon-Liste](/de/dokumentation/icons).

### Einfaches SVG

Kopiere die SVG-Dateien aus `node_modules/@db-ux/db-theme-icons/build/assets`, wenn du die Icons außerhalb von Komponenten brauchst.

### Autovervollständigung mit TypeScript

Trage die generierten Typen in deine `tsconfig.json` ein, um Vorschläge für Icon-Namen zu erhalten:

```json
{
	"compilerOptions": {
		"types": ["@db-ux/db-theme-icons"]
	},
	"include": ["node_modules/@db-ux/db-theme-icons/build/types/overwrite.d.ts"]
}
```

Für React oder Vue bindest du stattdessen `build/types/react.d.ts` oder `build/types/vue.d.ts` ein.

## Illustrative Icons

### Installation

```shell
npm i @db-ux/db-theme-illustrative-icons
```

### In React nutzen

Das Paket exportiert die Komponente `IllustrativeIcon`. Die Property `icon` nimmt den Icon-Namen, `size` die Größe in Pixeln.

```tsx
import { IllustrativeIcon } from '@db-ux/db-theme-illustrative-icons';

<IllustrativeIcon icon="luggage" size={64} />;
```

Die Liste der Namen wird als `IllustrativeIcons` exportiert, der passende Typ als `IllustrativeIconsType`.

### Als SVG nutzen

Für alle anderen Frameworks kopierst du die SVG-Dateien aus `node_modules/@db-ux/db-theme-illustrative-icons/build/assets`. Sie sind nach Themen in Ordnern gruppiert.

</DBSection>

## Fehlerbehebung

| Symptom                                                | Ursache und Lösung                                                                                                                                      |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Icons erscheinen als leere Kästchen oder Ersatzzeichen | Die Icon-Schrift ist nicht geladen. Importiere die Styles oder prüfe, ob die Asset-Pfad-Variante zu deinem Bundler passt.                               |
| Statt der DB-Icons erscheinen die Standard-Icons       | `default-font.css` ist nicht importiert oder `data-icon-variant="db"` fehlt am Element.                                                                 |
| Der Build scheitert mit `ENOENT` im Paket              | Die Assets wurden nie entschlüsselt. Siehe [Manuell entschlüsseln](/de/dokumentation/erste-schritte/entwicklung/pakete/db-theme#manuell-entschlüsseln). |
| Ein Icon-Name wird nicht erkannt                       | Den Namen gibt es nicht. Prüfe die Schreibweise in der [Icon-Liste](/de/dokumentation/icons).                                                           |

Wenn das nicht hilft, öffne ein Issue im [core-web-Repository](https://github.com/db-ux-design-system/core-web/issues/new/choose). Prüfe vorher, ob es das Issue schon gibt.

</DBSection>
