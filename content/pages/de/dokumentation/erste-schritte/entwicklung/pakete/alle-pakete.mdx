## Wie die Pakete zusammenhängen

Drei Schichten bauen aufeinander auf. Du installierst nur die oberste, die du brauchst – die darunterliegenden kommen mit.

| Schicht               | Paket                                                                               | Inhalt                                                       |
| --------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Framework-Komponenten | `@db-ux/react-core-components` und die Pendants für Angular, Vue und Web Components | Komponenten für ein Framework                                |
| Komponenten-Styles    | `@db-ux/core-components`                                                            | CSS und SCSS aller Komponenten, enthält die Schicht darunter |
| Tokens und Assets     | `@db-ux/core-foundations`                                                           | Farben, Abstände, Typografie, Density, Icons, Schriften      |

<DBNotification variant="standalone" semantic="informational" headline="Hinweis">
	`@db-ux/core-components` zieht `@db-ux/core-foundations` als Abhängigkeit mit. Bei `npm` passiert
	das automatisch. Bei `pnpm` installierst du beide explizit.
</DBNotification>

</DBSection>

## Themes und Assets

Alle Anleitungen für Framework-Pakete nutzen im Styling-Setup das Whitelabel-Theme, weil es ohne weiteren Zugang funktioniert. Produkte der Deutschen Bahn brauchen zusätzlich das DB Theme. Theme und Icons sind verschlüsselt und brauchen Zugangsdaten aus dem Marketingportal.

| Ziel                | Installation            | Anleitung                                                                             |
| ------------------- | ----------------------- | ------------------------------------------------------------------------------------- |
| Marke Deutsche Bahn | `@db-ux/db-theme`       | [DB Theme](/de/dokumentation/erste-schritte/entwicklung/pakete/db-theme)              |
| Marke S-Bahn        | `@db-ux/s-bahn-theme`   | [DB Theme](/de/dokumentation/erste-schritte/entwicklung/pakete/db-theme#s-bahn-theme) |
| Icons ohne Theme    | `@db-ux/db-theme-icons` | [Icons](/de/dokumentation/erste-schritte/entwicklung/pakete/icons)                    |

<DBNotification
	variant="standalone"
	semantic="warning"
	headline="DB Theme für DB-Produkte verpflichtend"
>
	Wenn du für die Deutsche Bahn baust, ist das DB Theme Pflicht. Ohne es bleiben Farben, Typografie

## Optionales Tooling

Keines dieser Pakete brauchst du für den Start. Ergänze sie, sobald deine erste Komponente erscheint.

| Paket                        | Zweck                                                                                                             | Empfehlung                       |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| `@db-ux/core-postcss-plugin` | Löst `var()`, `calc()`, `color-mix()` und `light-dark()` zur Build-Zeit auf und entfernt ungenutzte Deklarationen | Empfohlen für Produktions-Builds |
| `@db-ux/core-vite-plugin`    | Reduziert das CSS-Setup auf einen einzigen Import                                                                 | Empfohlen, wenn du Vite nutzt    |
| `@db-ux/core-eslint-plugin`  | Meldet falsche Komponentennutzung im Editor                                                                       | Optional, im Team aber hilfreich |
| `@db-ux/core-stylelint`      | Prüft dein CSS und SCSS gegen die Regeln des Design Systems                                                       | Optional                         |

Für KI-Coding-Agenten gibt es `@db-ux/mcp-server` und `@db-ux/agent-cli`. Beide sind auf der Seite [MCP Server](/de/dokumentation/lernen/mcp-server) beschrieben.
