## Wann du dieses Paket brauchst

Ohne Theme nutzen die Komponenten die Whitelabel-Standardwerte. Das DB Theme ersetzt sie durch die Marke der Deutschen Bahn. Du brauchst es für jede Website und Anwendung der Deutschen Bahn.

<DBNotification
	variant="standalone"
	semantic="warning"
	headline="Nur für Produkte der Deutschen Bahn"
>
	Der Code des Design Systems ist unter der Apache-2.0-Lizenz frei nutzbar. Das DB Theme nicht:
	Seine Design-Assets und Marken dürfen nur für Websites und Anwendungen der Deutschen Bahn
	verwendet werden. Fragen zur Marke beantwortet das Marketingportal.
</DBNotification>

Das Theme zieht drei Pakete als Abhängigkeiten mit. Du installierst sie nicht separat.

| Paket                                | Inhalt                                          |
| ------------------------------------ | ----------------------------------------------- |
| `@db-ux/db-theme-fonts`              | Die Schriften DB Neo Screen                     |
| `@db-ux/db-theme-icons`              | Die DB-Icon-Schrift und SVG-Icons               |
| `@db-ux/db-theme-illustrative-icons` | Illustrative Icons als SVG und React-Komponente |

</DBSection>

<DBSection spacing="small" width="auto">

## Vor der Installation

Einige Dateien des Pakets sind aus rechtlichen Gründen verschlüsselt. Sie werden bei der Installation entschlüsselt, dafür brauchst du zwei Zugangsdaten.

1. Öffne die [Seite DB Theme im Marketingportal](https://marketingportal.extranet.deutschebahn.com/marketingportal/Design-Anwendungen/db-ux-design-system/resources/db-theme) und melde dich an. Deep Links funktionieren vor der Anmeldung nicht – öffne den Link nach dem Anmelden erneut.
2. Kopiere die Werte von `ASSET_PASSWORD` und `ASSET_INIT_VECTOR`.
3. Lege im Projektstamm eine Datei `.env` an und trage sie in deine `.gitignore` ein.
4. Trage beide Werte in die `.env` ein.

```dotenv
ASSET_PASSWORD=<Wert aus dem Marketingportal>
ASSET_INIT_VECTOR=<Wert aus dem Marketingportal>
```

<DBNotification variant="standalone" semantic="warning" headline="Zugangsdaten nicht ins Git">
	Committe die Datei `.env` nie. In CI/CD übergibst du beide Werte stattdessen als geheime
	Umgebungsvariablen.
</DBNotification>

</DBSection>

## Installation

```shell
npm i @db-ux/db-theme
```

Ein `postinstall`-Skript entschlüsselt die Dateien automatisch.

### Manuell entschlüsseln

Wenn dein Setup Lifecycle-Skripte deaktiviert – zum Beispiel mit der Einstellung `ignore-scripts` –, bleiben die Dateien verschlüsselt. Führe die Entschlüsselungsskripte dann selbst aus, einmal pro Paket:

```shell
node node_modules/@db-ux/db-theme/build/scripts/index.js
node node_modules/@db-ux/db-theme-fonts/build/scripts/index.js
node node_modules/@db-ux/db-theme-icons/build/scripts/index.js
node node_modules/@db-ux/db-theme-illustrative-icons/build/scripts/index.js
```

</DBSection>

## Styling-Setup

Lade zuerst die Komponenten-Styles und danach das DB Theme. Das Theme überschreibt die Whitelabel-Standardwerte und bringt Schriften und Icons mit.

```css
/* index.css */
@layer db-ux, db-theme;

@import '@db-ux/core-components/build/styles/rollup.css' layer(db-ux);
@import '@db-ux/db-theme/build/styles/rollup.css' layer(db-theme);
```

Das ersetzt den Import des Whitelabel-Themes aus den Anleitungen der Framework-Pakete.

### Variante für deinen Bundler wählen

| Variante                           | Nutze sie, wenn                   |
| ---------------------------------- | --------------------------------- |
| `rollup.css`                       | du mit Vite oder Rollup baust     |
| `webpack.css`                      | du mit Webpack oder Next.js baust |
| `relative.css` oder `absolute.css` | du keinen Bundler nutzt           |

### Vite

Wenn Vite die Asset-Pfade nicht auflöst, ergänze einen Alias:

```ts
// vite.config.ts
import * as path from 'node:path';
import { defineConfig } from 'vite';

export default defineConfig({
	resolve: {
		alias: {
			'@db-ux': path.resolve('node_modules/@db-ux'),
		},
	},
});
```

## Erste Prüfung

Zeige eine beliebige Komponente an, zum Beispiel einen Button. Erscheint er im DB-Rot und in der Schrift DB Neo Screen, funktioniert das Theme. Erscheint er in den Whitelabel-Farben, fehlt der Theme-Import oder er wird vor den Komponenten-Styles geladen.

## Erweitertes Setup

Statt der kombinierten Theme-Datei kannst du jeden Teil einzeln laden. So bestimmst du, welche Helper-Klassen und Assets in deinem Bundle landen.

```css
/* Komponenten */
@import '@db-ux/core-components/build/styles/index.css';

/* Helper-Klassen der Foundation (optional) */
@import '@db-ux/core-foundations/build/styles/helpers/classes/all.css';
@import '@db-ux/core-foundations/build/styles/density/classes/all.css';
@import '@db-ux/core-foundations/build/styles/fonts/classes/all.css';
@import '@db-ux/core-foundations/build/styles/colors/classes/all.css';

/* Assets */
@import '@db-ux/db-theme-fonts/build/styles/rollup.css';
@import '@db-ux/db-theme-icons/build/styles/rollup.css';

/* Theme */
@import '@db-ux/db-theme/build/styles/index.css';
```

</DBSection>

## S-Bahn Theme

Für Produkte der S-Bahn liefert `@db-ux/s-bahn-theme` die regionalen Logos und die Markenfarben der S-Bahn. Es nutzt dieselben Zugangsdaten und dieselbe Entschlüsselung. Importiere es anstelle des DB Themes:

```shell
npm i @db-ux/s-bahn-theme
```

```css
/* index.css */
@layer db-ux, db-theme;

@import '@db-ux/core-components/build/styles/rollup.css' layer(db-ux);
@import '@db-ux/s-bahn-theme/build/styles/rollup.css' layer(db-theme);
```

Das S-Bahn Theme hängt von den DB-Schriften und DB-Icons ab, aber nicht von den illustrativen Icons.

</DBSection>

## Fehlerbehebung

| Symptom                                                                    | Ursache und Lösung                                                                                                |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `Environment variables ASSET_PASSWORD and ASSET_INIT_VECTOR must be set`   | Die Datei `.env` fehlt oder enthält nicht beide Werte. Ergänze sie und führe die Entschlüsselung erneut aus.      |
| Der Build scheitert mit `ENOENT` an einer Datei in `@db-ux/db-theme/build` | Die Assets wurden nie entschlüsselt. Führe die Entschlüsselungsskripte manuell aus.                               |
| Komponenten erscheinen in den Whitelabel-Farben                            | Das Theme ist nicht importiert oder wird vor den Komponenten-Styles geladen. Prüfe die Reihenfolge der `@layer`.  |
| Schriften oder Icons fallen auf Systemstandards zurück                     | Die Asset-Pfade passen nicht zu deinem Bundler. Wechsle die Variante der Theme-Datei oder ergänze den Vite-Alias. |
| Der Link ins Marketingportal öffnet die Startseite                         | Deep Links funktionieren vor der Anmeldung nicht. Melde dich an und öffne den Link erneut.                        |

Wenn das nicht hilft, öffne ein Issue im [core-web-Repository](https://github.com/db-ux-design-system/core-web/issues/new/choose). Prüfe vorher, ob es das Issue schon gibt.

</DBSection>
