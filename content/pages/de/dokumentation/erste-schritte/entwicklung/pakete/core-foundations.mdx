## Wann du dieses Paket nutzt

Nutze Core Foundation allein nur dann, wenn du die Tokens ohne Komponenten-Styles brauchst – zum Beispiel wenn du eigene Komponenten auf dem Design System aufbaust oder wenn du nur Icons und Schriften benötigst.

## Bevor du anfängst

Du brauchst:

- Ein Projekt, in dem du eigene Komponenten baust oder nur Tokens, Icons und Schriften brauchst.
- Node.js und einen Paketmanager. Die Befehle auf dieser Seite nutzen pnpm. Mit npm verwendest du `npm i` statt `pnpm add`.
- Einen unterstützten Browser: die letzten drei Versionen von Chrome und Edge, Firefox ESR und die letzten zwei Major-Versionen von Safari.

Für Produkte der Deutschen Bahn brauchst du zusätzlich Zugang zum Marketingportal für das [DB Theme](/de/dokumentation/erste-schritte/entwicklung/pakete/db-theme). Du kannst ohne ihn starten: Das Whitelabel-Theme funktioniert sofort, das DB Theme ergänzt du später.

</DBSection>

```shell
pnpm add @db-ux/core-foundations
```

## Styling-Setup

Importiere zuerst ein Theme – es enthält alle Tokens als CSS Custom Properties und deckt Light Mode und Dark Mode ab. Danach importierst du das Bundle mit den Helper-Klassen.

```css
/* index.css */
@layer whitelabel-theme, db-ux;

@import '@db-ux/core-foundations/build/styles/theme/rollup.css' layer(whitelabel-theme);
@import '@db-ux/core-foundations/build/styles/bundle.css' layer(db-ux);
```

Das Bundle setzt zwei Standardwerte: Density `regular` und Adaptive Coloring `neutral-bg-lvl-1`.

### Asset-Pfad-Variante wählen

| Variante       | Asset-Pfad                        | Nutze sie, wenn                                                 |
| -------------- | --------------------------------- | --------------------------------------------------------------- |
| `rollup.css`   | `@db-ux/core-foundations/assets`  | dein Bundler Paketpfade auflöst                                 |
| `webpack.css`  | `~@db-ux/core-foundations/assets` | du mit Webpack baust                                            |
| `relative.css` | `../../assets`                    | du Icons und Schriften in deinen eigenen public-Ordner kopierst |

### Optionale Helper-Klassen

Jede dieser Dateien macht eine Gruppe von Data-Attributen überall verfügbar. Importiere nur, was du nutzt.

```css
/* [data-divider] und [data-focus] überall nutzen */
@import '@db-ux/core-foundations/build/styles/helpers/classes/all.css' layer(db-ux);
/* [data-density] überall nutzen */
@import '@db-ux/core-foundations/build/styles/density/classes/all.css' layer(db-ux);
/* [data-font-size] überall nutzen */
@import '@db-ux/core-foundations/build/styles/fonts/classes/all.css' layer(db-ux);
/* [data-color] überall nutzen */
@import '@db-ux/core-foundations/build/styles/colors/classes/all.css' layer(db-ux);
```

## Erstes Token

Referenziere Tokens als CSS Custom Properties.

```css
.my-container {
	padding: var(--db-spacing-fixed-md);
}
```

Density und Farbe setzt du über Data-Attribute an einem Container, der sie an seine Kinder weitergibt.

```html
<div class="my-container" data-density="functional" data-color="successful-bg-lvl-1"></div>
```

Alle verfügbaren Tokens sind unter [Foundation](/de/dokumentation/foundation) aufgeführt.

</DBSection>

## Setup prüfen

Füge dieses Snippet in eine Seite ein. Es zeigt an einer Stelle, ob Tokens, Schrift und Icons laden.

```html
<div style="padding: var(--db-spacing-fixed-md)">
	<span data-icon="arrow_right">Text mit Icon</span>
</div>
```

| Prüfpunkt | Erwartet                                                                                                              | Wenn nicht                                                                                                                                                              |
| --------- | --------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tokens    | Der Container hat in den DevTools einen Innenabstand von 16 px.                                                       | Der Theme-Import fehlt. Ohne ihn hat `var()` keinen Wert und der Innenabstand ist 0.                                                                                    |
| Schrift   | In den DevTools des Browsers ist die gerenderte Schrift des Texts `OpenSans` – mit dem DB Theme `DB Neo Screen Sans`. | Der Browser findet die Schriftdateien nicht. Prüfe die Asset-Pfade aus dem Styling-Setup.                                                                               |
| Icon      | Vor dem Text erscheint ein Pfeil.                                                                                     | Der Browser findet die Icon-Schrift nicht. Im Netzwerk-Tab der DevTools schlägt eine Anfrage für eine `.woff2`-Datei fehl. Prüfe die Asset-Pfade aus dem Styling-Setup. |

</DBSection>

## Empfohlenes Tooling

Keines der beiden Pakete brauchst du für den Start. Ergänze sie, sobald dein erstes Token auflöst.

### PostCSS-Plugin

Reduziert die Bundle-Größe, indem es `var()`, `calc()`, `color-mix()` und `light-dark()` zur Build-Zeit auflöst und ungenutzte Deklarationen entfernt.

```shell
pnpm add @db-ux/core-postcss-plugin --save-dev
```

### Stylelint-Plugin

Prüft dein eigenes CSS und SCSS gegen die Regeln des Design Systems, zum Beispiel ob du Tokens statt fester Werte referenzierst.

```shell
pnpm add @db-ux/core-stylelint --save-dev
```

## Fehlerbehebung

| Symptom                                  | Ursache und Lösung                                                                                                    |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Custom Properties lösen zu nichts auf    | Es ist kein Theme importiert. Die Theme-Datei definiert die Tokens – das Bundle allein genügt nicht.                  |
| Icons und Schriften werden nicht geladen | Die Asset-Pfad-Variante passt nicht zu deinem Setup. Wechsle zwischen `rollup.css`, `webpack.css` und `relative.css`. |
| Data-Attribute haben keine Wirkung       | Die passende Helper-Klassen-Datei ist nicht importiert. Ergänze den Import für diese Gruppe.                          |

Wenn das nicht hilft, öffne ein Issue im [core-web-Repository](https://github.com/db-ux-design-system/core-web/issues/new/choose). Prüfe vorher, ob es das Issue schon gibt.

</DBSection>
