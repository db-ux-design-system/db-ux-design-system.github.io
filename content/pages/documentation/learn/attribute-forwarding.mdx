## No property needed for aria and data

Set `aria-*` and `data-*` attributes directly on a component. It forwards them to its **main element**, for most form components to the `<input>`, `<select>` or `<textarea>`.

<LearnAside>

The main element is the native element a component is built around, for example the `<button>` of a Button. Some more attributes are forwarded as well:

| Framework               | Also forwarded                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------- |
| React                   | `role`, `title`, `style`, `lang`, `dir`, `hidden`, `tabIndex`, event handlers such as `onClick` |
| Angular, Web Components | `role`, `title`, `style`; classes from `class` are added to the main element                    |
| Vue                     | All fallthrough attributes, but onto the outermost element – see the Vue step                   |

**Custom Select** is the exception in every framework: it keeps the attributes on its outer element. Use its properties, such as `label`, for the accessible name.

</LearnAside>

</LearnBlock>

<LearnBlock>

## React passes the props through

Pass the attributes as props. The component spreads them onto its main element.

```tsx
<DBButton
	aria-expanded={isOpen}
	aria-controls="filter-panel"
	data-testid="filter-toggle"
	onClick={toggle}
>
	Filter
</DBButton>
```

<LearnAside>

Foundation attributes such as `data-density`, `data-color` or `data-icon-variant` stay on the outermost element of the component, because they style everything inside it.

</LearnAside>

</LearnBlock>

<LearnBlock>

## Angular and Web Components move them off the tag

Set the attributes on the component tag. The component moves them to its main element and removes them from the tag.

```html
<db-button aria-expanded="false" aria-controls="filter-panel" data-testid="filter-toggle"
	>Filter</db-button
>
```

<LearnAside>

- **Selectors:** target the inner element in tests, CSS and scripts: `[data-testid="filter-toggle"]` instead of `db-button[data-testid="filter-toggle"]`
- **Angular bindings:** use `[attr.aria-expanded]="isOpen"`. Later changes on the tag are forwarded as well
- **`data-density`** stays on the tag, because it sets the density for everything inside
- **Table Body, Table Row, Table Footer, Table Header Cell and Table Data Cell** move the attributes only on the first render. Later changes on the tag are not passed on

</LearnAside>

</LearnBlock>

<LearnBlock>

## Vue keeps them on the outermost element

Vue sets the attributes on the outermost element of a component, which is the main element for most components. For form components, this is the wrapper, so an `aria-label` does not reach the form field.

```vue
<DBButton
	:aria-expanded="isOpen"
	aria-controls="filter-panel"
	data-testid="filter-toggle"
	@click="toggle"
>
	Filter
</DBButton>
```

<LearnAside>

This is the default behavior of Vue for [fallthrough attributes](https://vuejs.org/guide/components/attrs.html). It affects the components whose outermost element is not their main element:

| Component                                 | Attributes land on | Not on      |
| ----------------------------------------- | ------------------ | ----------- |
| Input, Textarea, Select, Checkbox, Switch | Wrapper `<div>`    | Form field  |
| Radio                                     | `<label>`          | `<input>`   |
| Accordion Item                            | `<li>`             | `<details>` |
| Table                                     | Wrapper `<div>`    | `<table>`   |

For form fields, use the component properties instead: `label` for the accessible name and, for Input, Textarea, Select and Checkbox, `ariaDescribedBy` to replace the automatic description.

</LearnAside>

</LearnBlock>
