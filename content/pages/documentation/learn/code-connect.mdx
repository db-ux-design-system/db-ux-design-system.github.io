## Figma properties drive the code

Code Connect links the components in Figma to their code. In Dev Mode, developers see the code snippet that matches the selected configuration of a component.

<LearnAside>

The design system uses two kinds of component properties in Figma:

1. **Design properties** change the visual appearance and are always visible on the first level, for example Size, Label or Disabled.
2. **⚙️ Code Connect properties** only matter for the generated code, not for the visual design. If you can configure them, they appear on the first level, marked with ⚙️. If not, they are handled in the background.

</LearnAside>

</LearnBlock>

<LearnBlock>

## ⚙️ properties only change the code

As a designer, you set design properties as usual. Properties marked with **⚙️** sit at the end of the properties list, come with pre-selected defaults and do not change the visual design.

<LearnAside>

### Design properties

These are the properties you see when you select a component instance in Figma. They change the appearance of the component and the generated code at the same time.

### Checkbox: with a configurable ⚙️ property

The Checkbox shows design properties such as `Checked`, `Indeterminate`, `Disabled`, `Validation`, `Show Required Asterisk`, `Show Label`, `Label` and `Show Message`. At the end of the list, the ⚙️ property `Required` is configurable. Its default value is pre-selected.

### Outline Button: without ⚙️ properties

Not every component has configurable ⚙️ properties. The Outline Button only shows design properties such as `Disabled`, `Size`, `Width`, `Show Icon Leading`, `Show Icon Trailing`, `Icon Leading` and `Text`. Its variant is passed to the code automatically.

## The ⚙️ Code Connect layer holds code-only values

Some components contain an internal **⚙️ Code Connect** layer for properties that exist in code but not in the design. Select the layer to see whether there is anything for you to set.

<LearnAside>

<img
	src="/assets/learn/code-connect/code-connect-layer.png"

	style={{ maxWidth: '40%' }}
/>

The layer shows one of two states:

### ➡️ Set properties

The component has configurable ⚙️ properties. They appear on the first level of the component, where you adjust them. Default values are pre-selected.

	alt="Code Connect layer with configurable properties for the Checkbox component"

### ❌ No property to set

The component passes its values to the code automatically, for example `variant="outlined"` for the Outline Button. There is nothing for you to configure.

## Read the snippet in Dev Mode

As a developer, select a component instance in **Dev Mode** and choose your framework in the Code Connect section of the Inspect panel. The snippet reflects every property, including ⚙️ properties and their defaults.

<LearnAside>

{/* TODO: This section needs review by a developer familiar with the Code Connect implementation. */}

1. Open a Figma file and switch to Dev Mode with the toggle in the bottom toolbar.
2. Select a component instance on the canvas.
3. In the Inspect panel on the right, find the Code Connect section, marked as "Connected".
4. Select your target framework, for example React, from the dropdown.
5. The snippet shows the current property configuration, including the values of ⚙️ properties.

### Property mapping

| Property type            | Configured by                    | Example properties                     | Reflected in code  |
| ------------------------ | -------------------------------- | -------------------------------------- | ------------------ |
| Design-relevant          | Designer (component first level) | `size`, `label`, `disabled`            | ✅ Yes             |
| Code-only (configurable) | Designer (⚙️ on first level)     | `required`, `checked`, `indeterminate` | ✅ Yes             |
| Code-only (automatic)    | Determined by variant            | `variant`, `noText`                    | ✅ Yes (automatic) |

The distinction only matters for the design workflow. In code, all properties are treated the same.

### Default values

⚙️ properties come with defaults. If a designer has not changed a value, the snippet uses the default. The snippet is therefore complete for the selected configuration.

## Connect your own components

Follow the [Figma Code Connect quickstart](https://developers.figma.com/docs/code-connect/quickstart-guide/ 'The official Figma guide to connect your own components to Code Connect.') to connect your own components.

<LearnAside>

To include a DB UX component in your snippet, call `instance.findInstance('DBButton').executeTemplate().example`.

- You need a valid Figma token with access to your component.
- The code shown in Figma is a string, so you can change it as you like.
- The design system generates the snippets for all frameworks in its CI/CD pipeline with the [Figma plugin script in core-web](https://github.com/db-ux-design-system/core-web/blob/main/packages/components/configs/plugins/figma/index.cjs). You can give this script to an AI agent to adapt the logic for your own components.

</LearnAside>
