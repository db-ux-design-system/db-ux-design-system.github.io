## You need an Angular project and Node.js

Any Angular project with **standalone components** works. The commands on this page use pnpm.

<LearnAside>

- **Package manager:** with npm, use `npm i` instead of `pnpm add`.
- **Browsers:** the last three versions of Chrome and Edge, Firefox ESR and the last two major versions of Safari.
- **Versions:** the showcases in the core-web repository run on Angular 21 and version 6 of the design system packages.
- **DB Theme:** products of Deutsche Bahn also need the DB Theme. You can start without it, because the whitelabel theme works right away.

### Start from an example instead

Instead of an empty project, you can copy the matching example project. It already contains the packages and the styling setup:

```shell
npx degit db-ux-design-system/examples/angular-example my-app
cd my-app
npm install
npm run dev
```

The examples use the whitelabel theme and an older version of the design system. Update the packages before you build on an example, and add the [DB Theme](/documentation/learn/db-theme-setup) for a product of Deutsche Bahn. All example projects are listed under [Start from an example project](/documentation/learn/examples).

</LearnAside>

</LearnBlock>

## Install three packages

The Angular components need both style packages: the component styles and the foundation underneath them.

```shell
pnpm add @db-ux/ngx-core-components @db-ux/core-components @db-ux/core-foundations
```

<LearnAside>

| Package                      | Contains                                      |
| ---------------------------- | --------------------------------------------- |
| `@db-ux/ngx-core-components` | The components as Angular components          |
| `@db-ux/core-components`     | The styles of the components                  |
| `@db-ux/core-foundations`    | Tokens, the whitelabel theme, fonts and icons |

</LearnAside>

</LearnBlock>

<LearnBlock>

## Load the styles in the right order

Import the theme first and the component styles after it in your global stylesheet. The `@layer` line fixes this order.

```css
/* src/styles.css */
@layer whitelabel-theme, db-ux;
@import '@db-ux/core-foundations/build/styles/theme/rollup.css' layer(whitelabel-theme);
@import '@db-ux/core-components/build/styles/bundle.css' layer(db-ux);
```

<LearnAside>

### Pick the file for your bundler

| File           | Use when                                               |
| -------------- | ------------------------------------------------------ |
| `rollup.css`   | The asset paths resolve against the package (default)  |
| `webpack.css`  | You build with Webpack                                 |
| `relative.css` | You copy icons and fonts into your own `public` folder |

</LearnAside>

</LearnBlock>

<LearnBlock>

## Let Angular resolve the fonts

Without output hashing in the development build, the fonts often fail to load. Set `outputHashing` to `media` in `angular.json`.

```json
"development": {
	"outputHashing": "media"
}
```

<LearnAside>

The full path is `projects.<name>.architect.build.configurations.development`. The production configuration already uses output hashing, so only the development configuration needs this setting.

</LearnAside>

</LearnBlock>

## Render a button to check the setup

Import `DBButton` into your standalone component. A button with an icon shows whether styles, font and icons load.

```ts
import { DBButton } from '@db-ux/ngx-core-components';
@Component({ imports: [DBButton],
	template: `<db-button variant="brand" icon="arrow_right">Add item to cart</db-button>`,
})
```

<LearnAside>

| Check  | Expected                                                                                       |
| ------ | ---------------------------------------------------------------------------------------------- |
| Styles | The button has a filled background in the brand color and rounded corners.                     |
| Font   | The DevTools show `OpenSans` as the rendered font – or `DB Neo Screen Sans` with the DB Theme. |
| Icon   | An arrow appears in front of the text.                                                         |

### Bind values and events

Form components support three ways to bind values: `ngModel`, `FormControl` and plain event binding. All three are documented in the [package README](https://github.com/db-ux-design-system/core-web/tree/main/output/angular).

</LearnAside>

## If something does not look right

Most setup problems come from the order of the styles or from the output hashing of the development build.

<LearnAside>

| Symptom                           | Cause and fix                                                                                                                                        |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Components render without styles  | The CSS import is missing, or the theme is loaded after the component styles. Make `@layer whitelabel-theme, db-ux;` the first statement.            |
| Fonts do not load                 | Output hashing is disabled in the development configuration. Set `"outputHashing": "media"` as shown in the previous step.                           |
| Icons are missing                 | The browser cannot find the asset files. A `.woff2` request fails in the Network tab. Switch between `rollup.css`, `webpack.css` and `relative.css`. |
| `db-button` is an unknown element | `DBButton` is missing in the `imports` of the component that uses it.                                                                                |
| PostCSS plugin has no effect      | The Angular CLI ignores JavaScript-based PostCSS configs. Use a `postcss.config.json`.                                                               |

If none of this helps, open an issue in the [core-web repository](https://github.com/db-ux-design-system/core-web/issues/new/choose). Please check first whether the issue already exists.

</LearnAside>

Neither plugin is required to get started. Add them once your first component renders.

### PostCSS plugin

Reduces the bundle size by resolving `var()`, `calc()`, `color-mix()` and `light-dark()` at build time and removing unused declarations.

```shell
pnpm add @db-ux/core-postcss-plugin --save-dev
```

```json
{
	"plugins": {
		"@db-ux/core-postcss-plugin": {}
	}
}
```

<DBNotification variant="standalone" semantic="informational" headline="JSON config required">
	The Angular CLI (`@angular/build:application`) only reads JSON-based PostCSS configs and loads
	plugins by name. Put the configuration in a `postcss.config.json` in your project root – it then
	works in both `ng build` and `ng serve`.
</DBNotification>

### ESLint plugin

Reports incorrect component usage directly in the editor.

```shell
pnpm add eslint @db-ux/core-eslint-plugin @typescript-eslint/parser --save-dev
```
