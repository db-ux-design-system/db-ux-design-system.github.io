## Start with a React project that is set up

Create a Vite project with React and set it up with the [React setup](/documentation/learn/react-setup 'Install the packages, load the styles and keep the colors intact in the build.'). **Check:** `pnpm dev` starts without errors.

<LearnAside>

### What you need

- Node.js and pnpm. With npm, use `npm create` and `npm i` instead of `pnpm create` and `pnpm add`
- Basic knowledge of React: components, JSX and the `useState` hook
- A supported browser: the last three versions of Chrome and Edge, Firefox ESR and the last two major versions of Safari

The tutorial was tested with Vite 8, React 19 and version 6 of the design system packages. The same form is designed in Figma in the [Figma tutorial](/documentation/learn/figma-tutorial).

### All setup commands

Create the project and install the packages:

```shell
pnpm create vite my-app --template react-ts
cd my-app
pnpm install
pnpm add @db-ux/react-core-components @db-ux/core-components @db-ux/core-foundations
pnpm add esbuild --save-dev
```

Delete `src/App.css`. Replace the content of `src/index.css`:

```css
/* src/index.css */
@layer whitelabel-theme, db-ux;

@import '@db-ux/core-foundations/build/styles/theme/rollup.css' layer(whitelabel-theme);
@import '@db-ux/core-components/build/styles/bundle.css' layer(db-ux);
```

The first line fixes the order of the cascade layers, so the theme always comes before the component styles.

Vite 8 minifies CSS with LightningCSS by default. It transforms the `light-dark()` function of the design system incorrectly, and colors break in the production build. Switch the minifier to esbuild:

```ts
// vite.config.ts
import react from '@vitejs/plugin-react';
import { defineConfig } from 'vite';

export default defineConfig({
	plugins: [react()],
	build: {
		cssMinify: 'esbuild',
	},
});
```

Then start the app with `pnpm dev`.

## Build the page structure

Wrap the page in a **Section** and a **Stack**. **Check:** "Contact us" appears in the bold `OpenSans` font.

```tsx
<DBSection spacing="medium" width="small">
	<DBStack gap="large">{/* Heading, later the form */}</DBStack>
</DBSection>
```

<LearnAside>

Replace the content of `src/App.tsx`:

```tsx
// src/App.tsx
import { DBHeadingH1, DBSection, DBStack } from '@db-ux/react-core-components';

const App = () => (
	<DBSection spacing="medium" width="small">
		<DBStack gap="large">
			<DBHeadingH1>Contact us</DBHeadingH1>
		</DBStack>
	</DBSection>
);

export default App;
```

- **Section** sets the outer spacing and limits the content width. `width="small"` keeps the form at a readable width.
- **Stack** arranges its children with an even gap. You use it again for the form fields.
- **Heading** renders a real `<h1>` with the typography of the design system.

You find the font under the rendered fonts in the DevTools. If the headline appears in the browser default font, the CSS import from the setup is missing.

</LearnAside>

## Add the form in a Card

Put the fields into a **Card**, each with a `label`. **Check:** five fields and a brand-colored button with an arrow appear.

```tsx
<DBCard spacing="medium">
	<form>{/* <DBInput label="Name" name="name" required /> … */}</form>
</DBCard>
```

<LearnAside>

Put the Card below the headline. This is the complete `src/App.tsx`:

```tsx
// src/App.tsx
import {
	DBButton,
	DBCard,
	DBCheckbox,
	DBHeadingH1,
	DBInput,
	DBSection,
	DBSelect,
	DBStack,
	DBTextarea,
} from '@db-ux/react-core-components';

const App = () => (
	<DBSection spacing="medium" width="small">
		<DBStack gap="large">
			<DBHeadingH1>Contact us</DBHeadingH1>

			<DBCard spacing="medium">
				<form>
					<DBStack gap="medium">
						<DBInput label="Name" name="name" required />
						<DBInput label="Email" name="email" type="email" required />
						<DBSelect label="Topic" name="topic">
							<option value="booking">Booking</option>
							<option value="refund">Refund</option>
							<option value="other">Other</option>
						</DBSelect>
						<DBTextarea label="Message" name="message" required />
						<DBCheckbox name="copy">Send me a copy</DBCheckbox>
						<DBButton type="submit" variant="brand" icon="arrow_right">
							Send message
						</DBButton>
					</DBStack>
				</form>
			</DBCard>
		</DBStack>
	</DBSection>
);

export default App;
```

That is why `label` is a required part of every field: screen readers read it out, and a click on the label focuses the field. `required` and `type="email"` use the validation of the browser.

**Check in detail:** a click on a label focuses the field. If the arrow is missing, the browser cannot load the icon font – look for a failed `.woff2` request in the Network tab of the DevTools.

</LearnAside>

## Show feedback after sending

Show a **Notification** once the form is sent. **Check:** a green "Message sent" appears after sending.

```tsx
const [sent, setSent] = useState(false);
// in onSubmit: event.preventDefault(); setSent(true);
<DBNotification semantic="successful" headline="Message sent" />;
```

<LearnAside>

This is the complete `src/App.tsx`:

```tsx
// src/App.tsx
import { useState, type FormEvent } from 'react';
import {
	DBButton,
	DBCard,
	DBCheckbox,
	DBHeadingH1,
	DBInput,
	DBNotification,
	DBSection,
	DBSelect,
	DBStack,
	DBTextarea,
} from '@db-ux/react-core-components';

const App = () => {
	const [sent, setSent] = useState(false);

	const handleSubmit = (event: FormEvent<HTMLFormElement>) => {
		event.preventDefault();
		setSent(true);
	};

	return (
		<DBSection spacing="medium" width="small">
			<DBStack gap="large">
				<DBHeadingH1>Contact us</DBHeadingH1>

				{sent && (
					<DBNotification
						variant="standalone"
						semantic="successful"
						headline="Message sent"
						closeable
						closeButtonText="Close"
						onClose={() => setSent(false)}
					>
						We will get back to you within two working days.
					</DBNotification>
				)}

				<DBCard spacing="medium">
					<form onSubmit={handleSubmit}>
						<DBStack gap="medium">
							<DBInput label="Name" name="name" required />
							<DBInput label="Email" name="email" type="email" required />
							<DBSelect label="Topic" name="topic">
								<option value="booking">Booking</option>
								<option value="refund">Refund</option>
								<option value="other">Other</option>
							</DBSelect>
							<DBTextarea label="Message" name="message" required />
							<DBCheckbox name="copy">Send me a copy</DBCheckbox>
							<div className="form-actions">
								<DBButton type="submit" variant="brand" icon="arrow_right">
									Send message
								</DBButton>
							</div>
						</DBStack>
					</form>
				</DBCard>
			</DBStack>
		</DBSection>
	);
};

export default App;
```

The notification has the role `status`, so screen readers announce it without moving the focus. `closeButtonText` sets the accessible name of the close button – the ESLint plugin of the design system reports a closeable notification without it. The `form-actions` wrapper around the button is used in the next step.

**Check in detail:**

- Send the empty form: the browser marks the first required field, and no notification appears
- Fill in name, email and message and send again: a green notification "Message sent" appears above the Card
- Close the notification with its close button: it disappears

## Add your own styles with tokens

Style with **tokens** instead of pixel values. **Check:** the button moves to the right edge of the Card.

```css
.form-actions {
	padding-block-start: var(--db-spacing-fixed-sm);
}
```

<LearnAside>

Add the complete rule to `src/index.css`, below the imports. The class `form-actions` is the wrapper around the button from the previous step.

```css
/* src/index.css */
.form-actions {
	display: flex;
	justify-content: flex-end;
	padding-block-start: var(--db-spacing-fixed-sm);
}
```

`--db-spacing-fixed-sm` is a spacing token of the Foundation. Use tokens instead of fixed pixel values for spacing, colors and sizes, so your styles follow the theme and the density. All tokens are listed under [Foundation](/documentation/foundation).

**Check in detail:** the button sits at the right edge of the Card, with a little more space above it.

</LearnAside>

## Build for production

Build the app and open the preview. **Check:** the preview at `http://localhost:4173` looks exactly like the development version.

```shell
pnpm build
pnpm preview
```

<LearnAside>

Switch your operating system to Dark Mode: page, Card and fields switch to dark colors in both versions. If colors look wrong only in the preview, the `cssMinify` setting from the setup is missing.

</LearnAside>
