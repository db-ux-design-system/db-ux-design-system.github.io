### When to use Custom Heading

Use Custom Heading only when interactive or non-text content is needed inside the heading. For plain text headings, Heading H1–H6 is the right choice.

<div className="guideline-examples">
	<GuidelineExample

		description="Use Custom Heading when links, icons, or badges are part of the heading."
	/>
	<GuidelineExample
		variant="dont"
		figmaUrl="https://embed.figma.com/design/GAQwQI1UNW8HRMXnr4q8DC/Doku--Heading?node-id=4002-27&embed-host=share"
		description="Don't use Custom Heading for plain text headings. Heading H1–H6 is designed for that and simpler to use."
	/>
</div>

### No skipping semantic levels

Maintain the order of semantic levels (1 → 2 → 3). Skipped levels create an incomplete outline and hinder navigation with assistive technologies.

<div className="guideline-examples">
	<GuidelineExample
		variant="do"
		figmaUrl="https://embed.figma.com/design/GAQwQI1UNW8HRMXnr4q8DC/Doku--Heading?node-id=4002-29&embed-host=share"
		description="Build the heading hierarchy without gaps: Level 1, then Level 2, then Level 3."
	/>
	<GuidelineExample
		variant="dont"
		figmaUrl="https://embed.figma.com/design/GAQwQI1UNW8HRMXnr4q8DC/Doku--Heading?node-id=4002-31&embed-host=share"
		description="Don't jump from Level 1 directly to Level 3. The missing level creates an incomplete outline for screen readers."
	/>
</div>

### One Level 1 per page

Use exactly one Semantic Level 1 per page as the top level of the document structure. Multiple Level 1 elements break the hierarchy and impair screen reader navigation.

<div className="guideline-examples">
	<GuidelineExample
		variant="do"
		figmaUrl="https://embed.figma.com/design/GAQwQI1UNW8HRMXnr4q8DC/Doku--Heading?node-id=4002-33&embed-host=share"
		description="Use exactly one Semantic Level 1 as the page title."
	/>
	<GuidelineExample
		variant="dont"
		figmaUrl="https://embed.figma.com/design/GAQwQI1UNW8HRMXnr4q8DC/Doku--Heading?node-id=4002-35&embed-host=share"
		description="Don't use multiple Semantic Level 1 on the same page. Screen readers lose orientation in the document structure."
	/>
</div>

### Visual hierarchy with size

When overriding size, maintain the visual hierarchy. Each level must be equal to or smaller than the previous one.

<div className="guideline-examples">
	<GuidelineExample
		variant="do"
		figmaUrl="https://embed.figma.com/design/GAQwQI1UNW8HRMXnr4q8DC/Doku--Heading?node-id=4002-37&embed-host=share"
		description="Ensure higher levels remain visually larger than or equal to lower levels."
	/>
	<GuidelineExample

		figmaUrl="https://embed.figma.com/design/GAQwQI1UNW8HRMXnr4q8DC/Doku--Heading?node-id=4002-39&embed-host=share"
		description="An inverted size order contradicts reading expectations and makes it harder to grasp page structure."
	/>
</div>

### Limit interactive elements

Limit interactive elements within the heading to what is necessary. Too many actions distract from the content and reduce clarity.
