## What the design system is

The DB UX Design System is the shared base for digital products of Deutsche Bahn. Design and development use the same Foundation, the same components and the same names – in Figma and in code.

This documentation covers **Generation 3**, the current generation. Its predecessor is Generation 2, formerly known as DB UI. If you still work with it, start with the [migration from DB UI](/documentation/get-started/migration).

</DBSection>

<DBSection spacing="small" width="auto">

## What it contains

| Part       | Contains                                                                                       | Documentation                                                                                      |
| ---------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Foundation | Tokens for colors, typography, spacing, density and more                                       | [Foundation](/documentation/foundation)                                                            |
| Components | Interface building blocks for design and code                                                  | [Components](/documentation/components)                                                            |
| Patterns   | Recurring solutions that combine several components                                            | [Patterns](/documentation/patterns)                                                                |
| Extensions | Additional libraries for specific domains, such as passenger information or data visualization | [Extensions](/documentation/extensions)                                                            |
| Themes     | The DB Theme and the S-Bahn Theme, which apply the brand to everything above                   | [DB Theme](/documentation/get-started/development/packages/db-theme)                               |
| Tools      | Figma libraries and plugins, code packages, the MCP Server for AI agents                       | [Design](/documentation/get-started/design), [Development](/documentation/get-started/development) |

The core of the system is the same for all products. Extensions build on it for specific domains.

### Platforms

The components are available for web: as CSS, as Web Components and for Angular, React and Vue. Native components for iOS (SwiftUI) and Android (Jetpack Compose) are developed in separate repositories – see [Native Platforms](/documentation/get-started/development/native).

</DBSection>

## How it is released

The design system follows Semantic Versioning: `MAJOR.MINOR.PATCH`.

| Release | Contains                                | Cadence                                                  |
| ------- | --------------------------------------- | -------------------------------------------------------- |
| Major   | Breaking changes                        | Planned, at least 2–3 months apart, announced in advance |
| Minor   | New features, fully backward-compatible | Aligned with the two-week sprint cycle                   |
| Patch   | Bug fixes and very small improvements   | As needed                                                |

Major and minor version numbers are kept in sync across design and development. The details, including all communication channels, are described under [Versioning & Releases](/documentation/releases/versioning).

</DBSection>

## What a status means

Every component, pattern and template has a status. It tells you how mature and reliable it is.

| Status     | Meaning                                                                                                   |
| ---------- | --------------------------------------------------------------------------------------------------------- |
| Concept    | Early approach, nothing is final. Usable as a design reference – a code implementation may not exist yet. |
| Beta       | Functional and largely stable. Minor changes may still occur. Test thoroughly and share feedback.         |
| Stable     | Mature and reliable. **Mandatory to use** as the UX standard.                                             |
| Legacy     | No longer actively developed, only critical bug fixes. Migrate to current content.                        |
| Deprecated | Will be removed in a future major release. Plan the replacement.                                          |

What to expect from each status in detail is described under [Content Status](/documentation/releases/content-status). The current status of every component is tracked on the [component status board](https://github.com/orgs/db-ux-design-system/projects/4/views/1).

</DBSection>

## How binding it is

| Part            | Obligation                                                                                   |
| --------------- | -------------------------------------------------------------------------------------------- |
| Stable content  | **Mandatory** as the UX standard                                                             |
| Beta content    | Recommended – test it thoroughly and share feedback                                          |
| Concept content | Design reference only, expect changes                                                        |
| DB Theme        | **Required** for all websites and applications of Deutsche Bahn, not allowed outside of them |

For questions about adopting the design system in your product, contact Luis Schroff, Product Owner of the design system: [luis.schroff@deutschebahn.com](mailto:luis.schroff@deutschebahn.com).

</DBSection>
