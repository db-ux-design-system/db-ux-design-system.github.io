## When to use this package

Use Core Components if you write HTML yourself – in plain pages, in a template engine, or in a framework for which no dedicated package exists. You get the component styles, but no component logic.

If you work with React, Angular, Vue or custom elements, install the matching framework package instead. Each of them already includes this package.

<DBNotification variant="standalone" semantic="informational" headline="Foundation included">
	This package pulls in `@db-ux/core-foundations` as a dependency. With `npm` that happens
	automatically. With `pnpm` you install both explicitly.
</DBNotification>

</DBSection>

<DBSection spacing="small" width="auto">

## Before you begin

You need:

- A project in which you write the HTML yourself, for example plain pages or a template engine.
- Node.js and a package manager. The commands on this page use npm. With pnpm, use `pnpm add` instead of `npm i`.
- A supported browser: the last three versions of Chrome and Edge, Firefox ESR and the last two major versions of Safari.

For products of Deutsche Bahn, you also need access to the Marketing Portal for the [DB Theme](/documentation/get-started/development/packages/db-theme). You can start without it: the whitelabel theme works right away, and you add the DB Theme later.

</DBSection>

## Styling setup

One import covers everything: all tokens from the Foundation and the styles of all components.

```css
/* index.css */
@layer whitelabel-theme, db-ux;

@import '@db-ux/core-foundations/build/styles/theme/rollup.css' layer(whitelabel-theme);
@import '@db-ux/core-components/build/styles/bundle.css' layer(db-ux);
```

### Pick the asset path variant

The theme file exists in three variants. They differ only in how they resolve the paths to icons and fonts.

| Variant        | Asset path                        | Use when                                             |
| -------------- | --------------------------------- | ---------------------------------------------------- |
| `rollup.css`   | `@db-ux/core-foundations/assets`  | Your bundler resolves package paths                  |
| `webpack.css`  | `~@db-ux/core-foundations/assets` | You build with Webpack                               |
| `relative.css` | `../assets`                       | You copy icons and fonts into your own public folder |

Write the markup as documented on the component page, then apply the component class.


## Check your setup

Render a button with an icon. It shows in one place whether styles, font and icons load.

```html
<button class="db-button" data-variant="brand" data-icon="arrow_right">Add item to cart</button>
```

| Check  | Expected                                                                                                            | If not                                                                                                                                                        |
| ------ | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Styles | The button has a filled background in the brand color and rounded corners.                                          | The CSS import is missing, or the theme is loaded after the component styles.                                                                                 |
| Font   | In the browser DevTools, the rendered font of the button is `OpenSans` – or `DB Neo Screen Sans` with the DB Theme. | The browser cannot find the font files. Check the asset paths from the styling setup.                                                                         |
| Icon   | An arrow appears in front of the text.                                                                              | The browser cannot find the icon font. In the Network tab of the DevTools, a request for a `.woff2` file fails. Check the asset paths from the styling setup. |

</DBSection>

## Recommended tooling

Neither package is required to get started. Add them once your first component renders.

### PostCSS plugin

Reduces the bundle size by resolving `var()`, `calc()`, `color-mix()` and `light-dark()` at build time and removing unused declarations.

```shell
pnpm add @db-ux/core-postcss-plugin --save-dev
```

### Stylelint plugin

Checks your own CSS and SCSS against the design system rules, for example whether you reference tokens instead of fixed values.

```shell
pnpm add @db-ux/core-stylelint --save-dev
```

## Troubleshooting

| Symptom                           | Cause and fix                                                                                                                                                         |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Components render without styles  | The CSS import is missing, or the theme is loaded after the component styles. Check that `@layer whitelabel-theme, db-ux;` is the first statement in your stylesheet. |
| Icons and fonts do not load       | The asset path variant does not match your setup. Switch between `rollup.css`, `webpack.css` and `relative.css`.                                                      |
| Tokens are undefined with `pnpm`  | `pnpm` does not hoist transitive dependencies. Install `@db-ux/core-foundations` explicitly.                                                                          |
| CSS output looks broken on Vite 8 | Vite 8 minifies with LightningCSS, which transforms modern CSS such as `light-dark()` incorrectly. Set `css.transformer: 'postcss'`.                                  |

If none of this helps, open an issue in the [core-web repository](https://github.com/db-ux-design-system/core-web/issues/new/choose). Please check first whether the issue already exists.
