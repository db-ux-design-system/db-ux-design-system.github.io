## When you need this package

Without a theme, the components use the whitelabel defaults. The DB Theme replaces them with the Deutsche Bahn brand. You need it for every website and application of Deutsche Bahn.

<DBNotification variant="standalone" semantic="warning" headline="Only for Deutsche Bahn products">
	The code of the design system is free to use under the Apache 2.0 license. The DB Theme is not:
	its design assets and trademarks may only be used for websites and applications of Deutsche Bahn.
	Questions about the brand go to the Marketing Portal.
</DBNotification>

The theme pulls in three packages as dependencies. You do not install them separately.

| Package                              | Contains                                      |
| ------------------------------------ | --------------------------------------------- |
| `@db-ux/db-theme-fonts`              | The DB Neo Screen fonts                       |
| `@db-ux/db-theme-icons`              | The DB icon font and SVG icons                |
| `@db-ux/db-theme-illustrative-icons` | Illustrative icons as SVG and React component |

</DBSection>

<DBSection spacing="small" width="auto">

## Before you install

Some files of the package are encrypted for legal reasons. They are decrypted during installation, which needs two credentials.

1. Open the [DB Theme page in the Marketing Portal](https://marketingportal.extranet.deutschebahn.com/marketingportal/Design-Anwendungen/db-ux-design-system/resources/db-theme) and sign in. Deep links do not work before login – open the link again after signing in.
2. Copy the values of `ASSET_PASSWORD` and `ASSET_INIT_VECTOR`.
3. Create a `.env` file in your project root and add it to your `.gitignore`.
4. Add both values to the `.env` file.

```dotenv
ASSET_PASSWORD=<value from the Marketing Portal>
ASSET_INIT_VECTOR=<value from the Marketing Portal>
```

<DBNotification variant="standalone" semantic="warning" headline="Keep the credentials out of Git">
	Never commit the `.env` file. In CI/CD, pass both values as secret environment variables instead.
</DBNotification>

</DBSection>

## Install

```shell
npm i @db-ux/db-theme
```

A `postinstall` script decrypts the files automatically.

### Decrypt manually

If your setup disables lifecycle scripts – for example with the `ignore-scripts` setting – the files stay encrypted. Run the decryption scripts yourself, once per package:

```shell
node node_modules/@db-ux/db-theme/build/scripts/index.js
node node_modules/@db-ux/db-theme-fonts/build/scripts/index.js
node node_modules/@db-ux/db-theme-icons/build/scripts/index.js
node node_modules/@db-ux/db-theme-illustrative-icons/build/scripts/index.js
```

</DBSection>

## Styling setup

Load the component styles first and the DB Theme after them. The theme overrides the whitelabel defaults and brings fonts and icons with it.

```css
/* index.css */
@layer db-ux, db-theme;

@import '@db-ux/core-components/build/styles/rollup.css' layer(db-ux);
@import '@db-ux/db-theme/build/styles/rollup.css' layer(db-theme);
```

This replaces the whitelabel theme import shown on the framework package pages.

<DBNotification variant="standalone" semantic="informational" headline="Why the order is reversed">
	On the framework package pages, the whitelabel theme comes first (`@layer whitelabel-theme,
	db-ux;`). There it is the base that the component styles build on. The DB Theme is an override: it
	comes last (`@layer db-ux, db-theme;`) so its values win over the whitelabel defaults. Both orders
	are correct for their setup – mixing them up shows the whitelabel colors.
</DBNotification>

### Pick the variant for your bundler

| Variant                          | Use when                          |
| -------------------------------- | --------------------------------- |
| `rollup.css`                     | You build with Vite or Rollup     |
| `webpack.css`                    | You build with Webpack or Next.js |
| `relative.css` or `absolute.css` | You do not use a bundler          |

### Vite

If Vite cannot resolve the asset paths, add an alias:

```ts
// vite.config.ts
import * as path from 'node:path';
import { defineConfig } from 'vite';

export default defineConfig({
	resolve: {
		alias: {
			'@db-ux': path.resolve('node_modules/@db-ux'),
		},
	},
});
```

## First check

Render any component, for example a button. If it shows the DB red and the DB Neo Screen font, the theme works. If it shows the whitelabel colors, the theme import is missing or loaded before the component styles.

</DBSection>

## Advanced setup

Instead of the combined theme file, you can load each part on its own. This gives you control over which helper classes and assets end up in your bundle.

```css
/* Components */
@import '@db-ux/core-components/build/styles/index.css';

/* Foundation helper classes (optional) */
@import '@db-ux/core-foundations/build/styles/helpers/classes/all.css';
@import '@db-ux/core-foundations/build/styles/density/classes/all.css';
@import '@db-ux/core-foundations/build/styles/fonts/classes/all.css';
@import '@db-ux/core-foundations/build/styles/colors/classes/all.css';

/* Assets */
@import '@db-ux/db-theme-fonts/build/styles/rollup.css';
@import '@db-ux/db-theme-icons/build/styles/rollup.css';

/* Theme */
@import '@db-ux/db-theme/build/styles/index.css';
```

</DBSection>

## S-Bahn Theme

For S-Bahn products, `@db-ux/s-bahn-theme` provides the regional logos and the S-Bahn brand colors. It uses the same credentials and the same decryption. Import it in place of the DB Theme:

```shell
npm i @db-ux/s-bahn-theme
```

```css
/* index.css */
@layer db-ux, db-theme;

@import '@db-ux/core-components/build/styles/rollup.css' layer(db-ux);
@import '@db-ux/s-bahn-theme/build/styles/rollup.css' layer(db-theme);
```

The S-Bahn Theme depends on the DB fonts and DB icons, but not on the illustrative icons.

</DBSection>

## Troubleshooting

| Symptom                                                                  | Cause and fix                                                                                      |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| `Environment variables ASSET_PASSWORD and ASSET_INIT_VECTOR must be set` | The `.env` file is missing or does not contain both values. Add them and run the decryption again. |
| The build fails with `ENOENT` on a file in `@db-ux/db-theme/build`       | The assets were never decrypted. Run the decryption scripts manually.                              |
| Components show the whitelabel colors                                    | The theme is not imported, or it is loaded before the component styles. Check the `@layer` order.  |
| Fonts or icons fall back to system defaults                              | The asset paths do not match your bundler. Switch the theme file variant or add the Vite alias.    |
| The Marketing Portal link opens the start page                           | Deep links do not work before login. Sign in and open the link again.                              |

If none of this helps, open an issue in the [core-web repository](https://github.com/db-ux-design-system/core-web/issues/new/choose). Please check first whether the issue already exists.
